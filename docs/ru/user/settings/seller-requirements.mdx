Требования к продавцам — это список задач, которые продавец должен выполнить до одобрения и начала работы на marketplace. Каждое требование — это то, что вы просите предоставить: принять условия, заполнить публичный профиль или загрузить документ для проверки.

Список одинаков для всех продавцов. В своём кабинете продавец видит задачи и прогресс, а в панели оператора на странице продавца — те же задачи и их статус. Обязательное требование нужно выполнить до одобрения; необязательное отображается как рекомендация.

Откройте **Настройки → Требования к продавцам** в панели оператора.

## Просмотр списка требований

В списке есть строка для каждого требования. Их порядок определяет порядок задач в кабинете продавца.

| Столбец | Значение |
|---|---|
| **Название** | Текст задачи для продавца и добавленная вами инструкция. |
| **Тип** | Что нужно предоставить или сделать. |
| **Обязательно** | Нужно ли выполнить требование до одобрения или оно только рекомендовано. |
| **Статус** | Включено ли требование. |

Строки можно перетаскивать; продавец увидит их в том же порядке.

### Требования по умолчанию

В новом marketplace Spree изначально настроено семь требований. Они описывают основные условия начала работы, поэтому обычно список дополняют, а не создают заново.

| Требование | Что делает продавец | Что можно настроить |
|---|---|---|
| **Принять условия** | Читает и принимает правила marketplace. | Текст условий, дату вступления в силу и необязательную ссылку на опубликованную копию. Продавцам, принявшим прежнюю редакцию до этой даты, предложат принять её заново. |
| **Заполнить профиль** | Заполняет публичный профиль, который видят покупатели. | Какие поля обязательны: описание, логотип, обложка и контактный адрес электронной почты. |
| **Адрес для выставления счетов** | Указывает адрес для счетов по комиссии. | — |
| **Адрес для возвратов** | Указывает адрес, куда покупатели отправляют возвраты. | — |
| **Способ доставки** | Предлагает хотя бы один способ отправки заказов. | Отдельных настроек нет. Требование также выполняется, если вы создали собственный способ доставки и открыли его для продавцов. Это удобно, когда marketplace сам отправляет все заказы. |
| **Коробка для отправки** | Указывает размер и вес упаковки. | — |
| **Минимальное число товаров** | Размещает не меньше указанного числа товаров. | Минимальное количество. |

Встроенное требование можно удалить и позднее добавить снова из списка типов. Обычно лучше отключить ненужное требование, например к коробке или адресу возврата для marketplace цифровых товаров: при отключении уже предоставленные данные сохраняются.

## Добавление требования

1. Нажмите **Добавить требование**.
2. Выберите **Тип** — он определяет задачу продавца.
3. Укажите **Название**, которое будет показано в списке задач.
4. Заполните **Инструкции**: что требуется и зачем.
5. Заполните дополнительные поля выбранного типа.
6. Оставьте включённым параметр **Обязательно**, если задача нужна до одобрения; выключите его, чтобы показать рекомендацию.
7. Нажмите **Сохранить**.

Новое требование появится в конце списка и сразу отобразится у всех продавцов, которые ещё не получили одобрение.

## Дополнительные типы требований

Семь встроенных требований покрывают базовые условия начала работы. Другие задачи создаются на основе типов ниже.

Большинство типов можно использовать в списке только один раз. Четыре типа, отмеченные как повторяемые, можно добавить несколько раз — например, чтобы запросить несколько документов или подтверждений. Тип, который разрешено использовать только один раз, не показывается при добавлении, если уже есть в списке; он снова станет доступен после удаления требования. Встроенные требования работают так же.

| Тип | Что делает продавец | Можно добавить повторно |
|---|---|---|
| **Счёт для выплат** | Подключает счёт для получения выплат. | Нет |
| **Обязательные дополнительные поля** | Заполняет выбранные вами дополнительные поля. | Нет |
| **Политика продавца** | Публикует собственные правила магазина. | Да |
| **Подтверждение продавца** | Подтверждает написанное вами заявление, например наличие прав на продажу товаров. | Да |
| **Ручная проверка** | Подтверждает готовность к проверке и оставляет запрошенную справочную информацию. Сотрудник отмечает задачу выполненной после проверки. | Да |
| **Документ** | Загружает файл для проверки, например свидетельство о регистрации. | Да |

Для типов **Подтверждение продавца**, **Ручная проверка** и **Документ** продавец может добавить комментарий к ответу. В типе **Документ** также указаны разрешённые форматы: PDF, JPEG, PNG, HEIC, WebP и Word.

Для продавца эти три задачи выглядят похоже, но отличаются тем, что происходит после ответа. Подтверждение засчитывается сразу после согласия продавца. Ручная проверка и документ ожидают одобрения вашей команды. Используйте ручную проверку, если факт может подтвердить только сотрудник, например регистрационный номер по государственному реестру. Подробнее — в разделе [«Подключение продавцов»](/user/sellers/onboarding).

<Note>Отдельного типа для текстового ответа или флажка нет. Для ответа текстом выберите **Обязательные дополнительные поля**, а для заявления, с которым продавец должен согласиться, — **Подтверждение продавца**.</Note>

### Дополнительные поля продавца

Тип **Обязательные дополнительные поля** позволяет запросить текст, например регистрационный номер компании или номер лицензии. Сами поля создаются не здесь.

Сначала создайте дополнительные поля для записей продавцов в разделе [«Дополнительные поля»](/user/settings/custom-fields), выбрав тип записи «Продавец». Затем добавьте требование этого типа и укажите поля, которые продавец должен заполнить.

Выбирайте только поля, на которые должен ответить продавец. Некоторые поля нужны вашей команде для внутренних заметок — например, имени менеджера продавца или результатов проверки. Если добавить такое поле в требование, его увидит продавец и должен будет заполнить до одобрения.

Ответы сохраняются в записи продавца, а не только в списке задач. Поэтому этот тип подходит для важных сведений, к которым нужно вернуться позже, например номера компании для проверки в реестре.

## Что запросить у продавца

Семь требований по умолчанию задают базовые условия. Дополнительные зависят от ассортимента и обязанностей вашей площадки.

Большинство marketplace запрашивает некоторые из следующих сведений:

- Регистрационный и налоговый номера компании — как **Обязательные дополнительные поля**.
- Подтверждение страхования ответственности — как **Документ**, если товары продавца могут причинить вред.
- Подтверждение прав на размещение товаров — как **Подтверждение продавца**, чтобы снизить риск продажи подделок.
- Опубликованные правила возврата — как **Политика продавца**, чтобы покупатели могли ознакомиться с условиями до покупки.

Отрасль также влияет на список требований:

| Категория marketplace | Что обычно запрашивают |
|---|---|
| **Еда и напитки** | Свидетельство о регистрации предприятия пищевой отрасли или соблюдении санитарных норм; подтверждение точности сведений об аллергенах. |
| **Косметика и товары для ухода** | Отчёт о безопасности продукции или его номер; ответственное лицо для рынка продаж. |
| **Электроника** | Декларацию соответствия для рынка; регистрацию по правилам утилизации электротехники, если она требуется. |
| **Добавки и товары для здоровья** | Регистрационный номер или уведомление для товара; подтверждение отсутствия медицинских заявлений. |
| **Алкоголь** | Лицензию продавца и подтверждение проверки возраста при доставке. |
| **Ювелирные изделия и драгоценные металлы** | Результат пробирного клеймения и сведения о происхождении материалов. |
| **Подержанные товары и перепродажа** | Описание проверки подлинности; используйте **Ручную проверку**, чтобы сотрудник подтвердил результат. |
| **Изделия ручной работы** | Подтверждение, что продавец самостоятельно изготавливает товары, если это важно для площадки. |

<Warning>Требование фиксирует только ответ продавца, но не проверяет его. Регистрационный номер в дополнительном поле останется просто текстом, пока сотрудник не сверит его с реестром. Для сведений, требующих проверки, используйте **Ручную проверку**, чтобы не забыть выполнить её.</Warning>

<Note>Список требований одинаков для всех продавцов. Если marketplace работает в нескольких категориях, не добавляйте всем подряд требования, актуальные только для части ассортимента. Оставьте общий список для условий, применимых ко всем, а остальное проверяйте индивидуально.</Note>

## Изменение требования

В меню строки выберите **Изменить**. Откроется та же форма, что и при создании. Здесь также есть параметр **Активно**: выключите его, чтобы больше не запрашивать требование, не удаляя его и ранее предоставленные ответы.

Для встроенного требования здесь можно изменить его особые параметры, например текст условий или минимальное число товаров. Они перечислены в разделе [«Требования по умолчанию»](#требования-по-умолчанию).

## Удаление требования

В меню строки выберите **Удалить** и подтвердите действие.

<Warning>Удаление требования также удаляет все предоставленные по нему данные, включая загруженные документы. Если нужно перестать задавать вопрос, отключите требование: ответы сохранятся.</Warning>
