## Summary

Add a Russian-language path through Spree's current merchant and seller documentation. The first release covers the work users asked to prioritize: setting up a store, entering and publishing catalog data, and running day-to-day operations for orders, inventory, and marketplace sellers. English remains the default and source language. Russian pages describe the shipped Spree 6.x product, use the existing Russian UI terminology, and are discoverable through Mintlify's language navigation.

## Key Decisions (do not deviate without discussion)

- **Translate the current v6.x user guides first.** The first release is for store owners, operators, and marketplace sellers. Developer guides, OpenAPI reference pages, integrations, and the frozen v5 documentation are outside this release.
- **Keep English as the source of truth and default route.** Russian pages mirror their English source page under `docs/ru/`; existing English URLs and v5 navigation remain unchanged.
- **Use Mintlify's native language navigation.** Add `ru` to the current v6.x navigation and validate the nested version/language configuration with the docs preview. Do not create a separate Russian docs site or custom language switcher. Mintlify documents native language navigation and Russian locale support in its [navigation guide](https://www.mintlify.com/docs/organize/navigation).
- **Do not auto-redirect the existing docs root in the first release.** Readers can choose Russian through the language menu. Keep current links, search entry points, and default English behavior stable.
- **Preserve product terms and executable examples.** Translate explanatory prose, headings, notes, tables, alt text, and navigation labels. Keep API fields, CLI commands, code, file paths, resource names, and exact dashboard labels intact; explain them in Russian around the examples.
- **Use the repository glossary and the Russian UI as terminology sources.** Extend `docs/localization/ru-terminology-6.0.2.md` only where user documentation introduces terms that the UI glossary does not cover. Keep one Russian term for each concept across operator and seller guides.
- **Screenshots must match the Russian interface.** For a translated workflow, capture the relevant dashboard or seller panel in Russian. Do not publish screenshots with English controls under Russian instructions when the control label is the step the user must find.
- **No parallel API reference translation in phase one.** The generated API reference, schemas, parameter names, and response fields remain canonical English. Russian guides may explain when to use an API, but must not fork generated API definitions.

## Design Details

### Audience and information architecture

The first release follows three user tasks in the order a new store encounters them:

1. **Настройка магазина** — prepare a store and its operating rules.
2. **Заполнение каталога** — enter, enrich, price, stock, and publish products.
3. **Ведение магазина и маркетплейса** — process orders, maintain inventory, and work with sellers.

Add Russian pages at the same relative paths below `docs/ru/user/` as their English sources. The localized navigation uses Russian section names and page titles while preserving the source page relationship. For example, `docs/user/products/adding-products.mdx` maps to `docs/ru/user/products/adding-products.mdx`.

### Page translation rules

- Keep a Russian page structurally aligned with its English source: frontmatter, section order, Mintlify components, tables, warnings, code blocks, image placement, and links.
- Translate title, description, page headings, prose, notes, callouts, table labels, image alt text, and any user-facing navigation label.
- Keep commands, code, API paths, property names, product states, and copied dashboard labels exact. Add a Russian explanation on first use when a term must remain English in the UI or API.
- Update internal links to the Russian destination where that page has shipped. Link to English for pages outside phase one and mark those links as English in the surrounding text where it would otherwise be surprising.
- Preserve feature caveats, permissions, plan restrictions, and destructive-action warnings. Translation must not make an optional or Enterprise-only feature sound available to every store.
- Keep examples internally consistent: a product's status, market locale, currency, stock location, and seller ownership must agree across a guide's steps and screenshots.

### Screenshots and other media

Store Russian captures under a dedicated `docs/images/ru/user/...` tree, matching source-page folders and filenames where practical. Capture at a consistent viewport and with seeded demo data. Review each image for readable text, correct Russian controls, visible focus/selection state, and sensitive values. Reuse neutral diagrams and product photos; recapture dashboard screenshots whose English labels are part of an instruction. Avoid embedding long UI copy in diagrams when a caption can carry it as text.

### Translation and product review

Translate page batches by workflow, not by file alphabetically. A translator or editor checks natural Russian and glossary consistency; a Spree maintainer checks each sequence against the live v6.x interface and the documented feature. Seller workflows receive a seller-role review in addition to an operator review. Pages with screenshots are not approved until the screenshot and the written step use the same Russian label.

## Migration Path

1. **Inventory and navigation audit.** Compare the proposed page list with the v6.x user navigation in `docs/docs.json`; identify source pages, stale or unlinked pages, references to UI labels, screenshot needs, and cross-links. Confirm which pages belong to catalog entry, setup, and daily operations.
2. **Russian docs foundation.** Create the Russian page tree, add the v6.x `ru` language navigation, set Russian titles and group names, and add the language switcher without changing the English default or v5 navigation. Preview the small quickstart pilot before scaling the pattern.
3. **Translate setup and first-store path.** Translate the overview and quickstart, then store details, Markets, sales channels, marketplace/seller requirements, payment, tax, delivery, locations, email, staff, and role instructions. Verify the setup order against the current onboarding checklist.
4. **Translate catalog entry and publishing.** Translate product creation, categories, variants, options, media, collections, custom fields, product types, import/export, translations, catalog visibility, pricing, and stock entry. Validate every screen label and screenshot against the Russian dashboard.
5. **Translate ongoing operations.** Translate order processing, drafts, returns/exchanges/claims, stock transfers and purchase orders, suppliers, seller onboarding and panel workflows, seller product/order work, commissions, payouts/transfers, and reports. Verify operator and seller permissions separately.
6. **Cross-link and review.** Link the translated workflows in sequence. Check internal links, page anchors, screenshots, locale navigation, search results, and English fallback links. Run a technical review against the current UI and feature availability; record unresolved translation choices in the glossary.
7. **Preview and publish.** Run the repository's docs preview (`pnpm docs:dev`), inspect English and Russian v6.x navigation, and confirm v5/English URLs still resolve. Publish through the existing docs deployment after content and terminology review.
8. **Maintain with each release.** When v6.x user pages or dashboard flows change, compare the affected English page IDs with their Russian counterparts. Update Russian copy and screenshots in the same release where practical; mark an out-of-date page for review rather than silently presenting stale steps. Keep a parity list so new user pages enter the translation inventory.

## Constraints on Current Work

- Do not edit English source user pages solely to make translation easier; fix product behavior or source inaccuracies in their own change and then mirror the correction in Russian.
- Do not change `docs.json` routing for English or v5 as part of a Russian content batch.
- Do not translate the old `docs/v5/` tree in this plan.
- Do not translate generated API schemas or alter request/response identifiers.
- Do not add screenshots containing real customer, seller, API-key, or payment data. Use seeded examples only.
- Keep the existing deployed Russian admin/seller UI glossary aligned with published dashboard labels; this plan covers documentation content, not another pass over UI translations.
