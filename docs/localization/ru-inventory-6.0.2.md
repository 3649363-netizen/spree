# Russian localization inventory: Spree 6.0.2

This inventory records the translation surfaces present in the upstream `v6.0.2` checkout and the current Russian localization coverage. It distinguishes prepared draft resources from locale registration and runtime activation.

## Interfaces and dictionaries

| Surface | Source of strings | Existing bundled locales | Russian status |
|---|---|---|---|
| Operator dashboard | `packages/dashboard/src/locales/*.json` | `ar`, `de`, `en`, `es`, `fr`, `ja`, `pl`, `vi`, `zh-CN` | Draft covers 4,453/4,453 English keys; not registered |
| Shared dashboard UI | `packages/dashboard-core/src/locales/*.json` | `ar`, `de`, `en`, `es`, `fr`, `ja`, `pl`, `vi`, `zh-CN` | Draft covers 1,385/1,385 English keys; not registered |
| Seller dashboard | `packages/seller-dashboard/src/locales/*.json` | `ar`, `de`, `en`, `fr`, `ja`, `pl`, `vi`, `zh-CN` | Draft covers 639/639 English keys; not registered; Spanish is also absent |
| Operator dashboard starter | `packages/dashboard-starter/src/locales/en.json` | `en` only | Starter-specific strings need a Russian resource when customized |
| Seller dashboard starter | `packages/seller-dashboard-starter/src/locales/en.json` | `en` only | Starter-specific strings need a Russian resource when customized |
| Example dashboard plugin | `packages/dashboard-plugin-example/src/locales/en.json` | `en` only | Example/plugin keys are separate from the core dictionaries |

Resource totals: 26 shared/operator/seller locale JSON files (9 + 9 + 8), with no Russian file among them, plus three English-only custom resources (two starters and one example plugin). Russian drafts have complete key coverage for the three dashboard dictionaries but remain outside their locale-loader paths. The seller dashboard also has no Spanish resource, unlike the operator and shared packages.

The UI dictionaries are JSON resources loaded by the corresponding i18n setup modules (`packages/dashboard/src/i18n-setup.ts`, `packages/dashboard-core/src/lib/i18n.ts`, and `packages/seller-dashboard/src/i18n.ts`). Each module discovers locale files with `import.meta.glob` (excluding English from the additional-locale glob), and exposes the bundled locale codes to the UI. Adding `ru.json` to only one package registers Russian only for that package. The operator dashboard, shared UI, and seller dashboard therefore need independent Russian resources; translating the shared package alone will not translate either full interface.

## Server and API messages

Rails locale YAML files are vendored in the repository, not generated by the UI JSON dictionaries:

- Core: `spree/core/config/locales/`
- API: `spree/api/config/locales/`
- Email subsystem: `spree/emails/config/locales/`

Each of these folders contains the same 44 locale YAML files, including `en.yml` and `ru.yml`. The existence of `ru.yml` only establishes that Russian keys are present in the file; it does not establish parity with English or complete Russian coverage. The server/API locale layer and frontend locale layer must be reviewed independently.

## Storefront / buyer experience

The public buyer storefront is not present as a source package in this checkout. Spree's app generator clones it from [`spree/storefront`](https://github.com/spree/storefront) into `apps/storefront/` (`packages/create-spree-app/src/constants.ts`, `packages/create-spree-app/src/storefront.ts`). For this work, stable commit [`09acd70ab7e802f246dd767545e391d449c6166b`](https://github.com/spree/storefront/commit/09acd70ab7e802f246dd767545e391d449c6166b) was selected: its `package.json` depends on `@spree/sdk` `^6.0.2`. The local companion checkout is `/root/spree-storefront-ru`, branch `feature/russian-localization-6.0.2-ru`. Its Russian message resource matches all 609 English leaves and preserves all interpolation variables; 605 copy values are translated while four dynamic/data literals remain unchanged. Locale registration remains a later step. This is a source pin, not proof of runtime compatibility with a deployed Spree server.

## Strings to keep as data, and remaining audits

Do not translate locale codes (`ru`, `en`, `zh-CN`), currency codes (`RUB`, `USD`), SKU/order/customer identifiers, URLs, API enum values, or Liquid variable names. These may have localized labels in the UI, but their underlying values must remain stable. Liquid tags, filters, and HTML attributes are template structure, not copy. The rule applies across all surfaces: operator UI, seller UI, checkout/storefront, API-backed data, and transactional mail.

| Interface | Values/markers to preserve verbatim | Localizable presentation around them |
|---|---|---|
| Operator dashboard | Store/resource IDs, SKUs, order numbers, API enum values, locale tags, currency codes, URL examples, numeric input examples | Field labels, enum labels, validation/help text, accessible names, status badges |
| Seller dashboard | Seller/store IDs, SKUs, order/fulfillment identifiers, payout/payment provider codes, currency codes, API enum values | Seller workflow labels, form copy, empty/error states, accessible names |
| Buyer storefront | Product SKUs/IDs, variant option values when seller-entered, order numbers, currency codes, URLs | Product UI, checkout steps, delivery/payment labels, confirmation/error copy; source is outside this checkout |
| Rails/API | Translation keys, HTTP/status codes, enum values, interpolation placeholders | Human-readable validation, authorization, and business-rule messages |
| Transactional email | Liquid tags/filters/variable names, URLs, IDs, order numbers, SKUs, currency/amount values | Subject/body copy, date/number formatting, localized labels around interpolated data |

### Literal source findings

A targeted scan of JSX child text found two production UI literals bypassing the dictionaries. Both now resolve through shared dashboard translations:

- `Soon` badge in `packages/dashboard-core/src/components/settings-sidebar.tsx` (`SettingsItem`) uses `admin.common.soon`.
- `Toggle Sidebar` accessible name in `packages/dashboard-ui/src/ui/sidebar.tsx` (`SidebarTrigger`) is supplied by dashboard-core as `admin.common.toggle_sidebar`, including its screen-reader label.

The same bounded scan also found test probes and dynamic translated labels, which are not additional production literals. Static placeholder hits in the operator dashboard include numeric examples (`15`, `100`, `10`, `0`) and OAuth/tracking URL examples (`https://example.com/oauth/callback`, `https://carrier.example/track?num=:tracking`). Keep those examples as data formats; translate nearby explanatory copy, not the values. Percentage signs and currency symbols are formatted values. The date-picker component uses the active UI locale for month and weekday names (`packages/dashboard-ui/src/ui/calendar.tsx`), so Russian date labels depend on the UI locale being registered.

All 21 Liquid email templates were scanned for visible English body text and static `alt`, `title`, `aria-label`, and `placeholder` values after excluding front matter, Liquid comments/tags, and HTML markup. No untranslated static copy was found; dynamic item names remain store data.

### Stage 4 coverage verification

Parity checks compare flattened keys and interpolation placeholders against each English source. The dashboard drafts cover all 6,477 UI keys across operator (4,453), shared (1,385), and seller (639) interfaces. All 68 audited i18next plural groups are complete: 43 operator, 22 shared, and 3 seller groups have `_one`, `_few`, `_many`, and `_other` forms. The separate storefront draft has 609 matching keys, with all four ICU plural messages carrying Russian categories. Rails parity is Core 1,349/1,349, API 24/24, and Emails 94/94, with no placeholder mismatches; Core has 49 and Emails has 2 complete `one/few/many/other` plural groups. Dashboard and storefront formatters use their active UI/route locale. Email templates format dates through the locale-aware `date` filter and amounts through the Money gem's I18n backend; the mailer renders inside the selected store locale. Verified Russian output examples are `1 234 567,89 ₽`, `1 234 567,89 $`, and `6 ноября 2026 г. в 17:34`; plural selection gives `one` for 1, `few` for 2, `many` for 5, and `other` for 1.5. The targeted literal scan is not a complete static analysis: dynamic labels, component props, runtime API errors, plugin screens, and storefront-specific email copy remain separate review surfaces. The UI JSON drafts and storefront resource remain outside their locale-loader paths; adding `ru` to the selectors is stage 5.

## Scope boundary

This inventory is bounded to the tracked paths in the Spree 6.0.2 repository. It does not count dynamic resource translations (product, category, option, policy, or store content) as interface dictionary keys: those are store data managed through Spree's resource translation API and need a separate content migration and review process.
